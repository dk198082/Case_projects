Extract the Production Priority Board's design system separately; ask whether to apply it only once it is ready. Do not change existing screens without separate application approval.

**Why:** The user explicitly requested extraction followed by an application decision, not an automatic redesign or migration.

**How to apply:** Approval of an extraction pilot or continuation does not authorize screen changes. Complete the required component set and present the finished system, then ask whether to apply it before changing the board or any existing canvas mockup.

The user is considering this design system for a **new application not yet created** in the separate Field Service Calendar project. Do **not** apply it to the existing Field Service Calendar app. No board or canvas migration was approved either.

**Why:** The user clarified the intended future target after the extraction was presented and explicitly excluded the existing Field Service Calendar app.

**How to apply:** Treat future reuse in the new app as a separate request. A reusable template can transfer visual language between projects; using the exact shared web components in another project also requires bringing the design-system package into that project's workspace.
